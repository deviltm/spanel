# spanel — панель проксирования веб-интерфейсов через SSH (без агента)

**Режим: «Без агента, через SSH».** На удалённом сервере не нужно ничего
устанавливать — достаточно работающего `sshd` и веб-сервиса. Панель выступает
как SSH-клиент: добавляете сервер (хост, порт, пользователь, **ключ или
пароль** — способ аутентификации можно менять в любой момент), указываете порт
удалённой веб-панели (например `127.0.0.1:8006`) — панель открывает канал
`direct-tcpip` внутри постоянного SSH-соединения и проксирует трафик браузера
через него. Поддерживаются HTTP, HTTPS (в т.ч. самоподписанные бэкенды),
WebSocket, SSE, chunked/streaming и загрузки файлов.

> ⚠️ **Ограничение по NAT:** режим работает только если SSH-порт сервера доступен
> снаружи (публичный IP или проброс портов на роутере). Для серверов за NAT без
> проброса нужен либо reverse SSH-туннель, либо агент, либо VPN (WireGuard/Tailscale).

## Возможности

- **Веб-форма добавления сервера**: все параметры SSH + выбор способа
  аутентификации (приватный ключ / пароль), passphrase для зашифрованного ключа.
- **Проверка подключения перед сохранением**: TCP-доступность, SSH-рукопожатие,
  аутентификация, отпечаток host key, задержка (`POST .../ssh/test`).
- **Host key verification**: TOFU (подтверждение при первом подключении) / Strict /
  Disabled. При смене ключа сервера подключение блокируется до подтверждения.
- **Несколько веб-сервисов на один сервер** через одно SSH-соединение
  (мультиплексирование каналов, без лишних локальных портов на панели).
- **Шифрование секретов**: приватные ключи, пароли ключей и SSH-пароли хранятся в
  AES-256-GCM; мастер-ключ — вне БД (ENV / файл). Секреты не возвращаются через API
  и не попадают в логи; в UI показывается `[ключ сохранён]`.
- **Защита SSRF**: целевые хосты ограничены `127.0.0.1` / `::1` / `localhost`
  (расширение — отдельной настройкой). Панель **не выполняет команды** на сервере —
  только открытие TCP-каналов к разрешённым адресам.
- **Отказоустойчивость**: keepalive 15s, авто-реконнект с экспоненциальной
  задержкой (1s→60s), восстановление туннелей после рестарта панели.
- **Понятные статусы и ошибки**: `auth_error`, `host_key_error`, `timeout`,
  `key_decrypt_error`, `target_unreachable`, подсказка про `AllowTcpForwarding`.
- **Аудит действий** (`GET /api/v1/audit`).

## Требования к удалённому серверу

В `/etc/ssh/sshd_config` должно быть включено пробрасывание каналов:

```text
AllowTcpForwarding yes
PubkeyAuthentication yes        # рекомендуется; PasswordAuthentication — по желанию
```

## Быстрый старт (Linux/macOS)

```bash
git clone <repo> && cd spanel

# 1. Установка компонентов (python venv + зависимости + .env с мастер-ключом)
./scripts/install.sh

# 2. Запуск панели (передний план, Ctrl+C — остановка)
./scripts/run.sh

#    или в фоне:
./scripts/run.sh --bg
./scripts/status.sh      # статус + последние строки лога
./scripts/stop.sh        # остановка
```

Панель доступна на `http://localhost:8080` (настраивается в `.env`).

### Сценарий работы

1. Открыть панель → **«Добавить сервер»** → заполнить SSH-хост, порт, пользователя,
   выбрать **ключ или пароль**, вставить приватный ключ (+ passphrase при необходимости).
2. Нажать **«Проверить подключение»** — панель покажет доступность, результат
   аутентификации и отпечаток host key; подтвердить доверие (TOFU).
3. Добавить **веб-сервис**: целевой хост `127.0.0.1`, порт веб-панели (например `8006`),
   протокол `http`/`https`, публичный slug.
4. Открывать сервис через публичный URL панели — трафик идёт через SSH-туннель.

## Скрипты установки и запуска

| Скрипт | Назначение |
|---|---|
| `scripts/install.sh` | Создание `.venv`, установка зависимостей из `requirements.txt`, подготовка `./data` и `.env` (с генерацией `SECRETS_ENCRYPTION_KEY`) |
| `scripts/run.sh` | Запуск панели (uvicorn); `--bg` — в фоне (лог `data/spanel.log`, pid `data/spanel.pid`) |
| `scripts/stop.sh` | Остановка фонового процесса (SIGTERM → SIGKILL) |
| `scripts/status.sh` | Проверка запущена ли панель + хвост лога |
| `scripts/gen_key.sh` | Генерация мастер-ключа шифрования; `--write-env` — записать в `.env` |
| `scripts/spanel.service` | Unit-файл systemd для продакшена |

## Конфигурация (`.env`)

См. `.env.example`:

- `SECRETS_ENCRYPTION_KEY` — base64(32 байта), AES-256-GCM шифрование приватных
  ключей/паролей. **Не теряйте**: без него расшифровать сохранённые секреты нельзя.
- `PANEL_HOST` / `PANEL_PORT` — адрес панели (по умолчанию `0.0.0.0:8080`).
- `BASE_DOMAIN` — базовый домен публичных URL сервисов (`https://<slug>.<domain>`).
- `SPANEL_DATA_DIR` — каталог данных (SQLite БД).

## API (кратко)

| Метод | Путь | Описание |
|---|---|---|
| `POST` | `/api/v1/servers` | Создать SSH-сервер (ключ или пароль) |
| `POST` | `/api/v1/servers/{id}/ssh/test` | Проверка: TCP → handshake → auth → host key → latency |
| `POST` | `/api/v1/servers/{id}/hostkey/confirm` | Подтвердить отпечаток host key (TOFU) |
| `POST` | `/api/v1/servers/{id}/connect` / `disconnect` | Установить/закрыть SSH-соединение |
| `POST` | `/api/v1/servers/{id}/services` | Добавить веб-сервис (target host:port, http/https, slug) |
| `POST` | `/api/v1/services/{id}/check` | Health-check целевого порта через туннель |
| `GET` | `/api/v1/audit` | Журнал действий |
| any | `/proxy/{slug}/...` | Проксирование трафика к сервису через SSH-канал |

Ответы API никогда не содержат приватные ключи и пароли.

## Docker

```bash
export SECRETS_ENCRYPTION_KEY=$(./scripts/gen_key.sh)
docker compose up -d --build
```

Данные БД — в volume `spanel_data`.

## systemd (продакшен)

```bash
sudo cp -r . /opt/spanel && cd /opt/spanel && ./scripts/install.sh
sudo cp scripts/spanel.service /etc/systemd/system/
sudo systemctl daemon-reload && sudo systemctl enable --now spanel
```

## Test-скенарий (e2e)

`tests/fake_remote.py` эмулирует «удалённый сервер» (paramiko sshd на :2222 +
веб-панель на :8006) для проверки туннелирования без реального сервера.
